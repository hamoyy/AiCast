# 2026-10-10

## 设置页七个权限开关的实际效力（代码核对结果）

回答用户「权限开关分别代表什么」时逐个对着 Server.kt 核了一遍，结论值得记下来，
因为 UI 上七个开关排成一列看起来等价，实际只有三个生效：

| 开关 | UI 文案 | 默认 | 代码里实际把关的位置 |
|---|---|---|---|
| render | 投送内容 render | **开** | Server.kt:227 (`POST /render`)；并被 hasPerm 复用给 285/320/335/403（`/theme` 增删、`/media` 上传删除） |
| message | 增量消息 message | **开** | Server.kt:462 (`POST /message`) |
| param | 参数控制 param | 关 | Server.kt:484 (`POST /param`)，覆盖 brightness/fontScale/theme/volume（`Params.supportedKeys`） |
| screen / system / screenshot | 屏幕/系统/截屏 | 关 | **全仓无引用**，没有对应端点（grep 只命中 Prefs/Settings/ClockScreen 的标签表） |
| eval | JS 注入 | 关 | 昨天删光了：`CommandBus.eval()` 零调用方，capabilities 也不再上报 |

两道门的顺序别搞混：先 `mode/token` 门（不过 → **401**），再逐项权限门（不过 → **403 permission_denied**）。
公开模式只是跳过第一道门，第二道照常生效 —— 电视之所以能投，是因为 render/message 默认开着。

默认值来自 `Prefs.isOpen` 的 else 分支：`permission in listOf("render","message")`。
存储：`aiface.xml` 里的 `allow_<permission>`（eval 例外，是 `allowEval`）。

顺带三个待办：`/info.open` 会把这些空项报给 agent、`docs/DESIGN.md` §5/§10 也还把它们
写成既有端点、`GET /history` 不查权限（公开模式下任何人可读）。

## 收敛实施（commit 6fd5a3c，仅编译验证，未上真机）

用户决策：① 去掉无效选项；② **除 render 开关外其余一律常开且不再提供选项**。

- `Prefs.openable` = `listOf("render")`；新增 `alwaysOpen = listOf("message","param")`
- **`isOpen` 只剩 `render` 读 `allow_render`，其余一律 true** —— 这是本次最容易
  埋雷的一处：如果照旧读 `allow_message`，老设备上存过的 `false` 会把门永久关死，
  而 UI 已经没有开关能改回来了
- `openList()` = 开关现值 + 常开项，所以 `/info.open` 仍会报 message/param
  （语义变成「当前放行项」，而非「可拨开关集合」）—— 不报的话 agent 会误判这两项不可用
- `/info.app` 去掉 `evalEnabled`；`Prefs.evalEnabled` 属性一并删除
- `ClockScreen.permLabel` / `SettingsScreen.permLabelZh` 同步瘦身；设置页补一行
  「增量消息 message、参数控制 param 默认常开，不再提供开关」

`Server.kt` 里 `isOpen("message"/"param")` 的两个检查保留未删 —— 现在恒为真，
但它们标出了真正的把关点，将来若重新变成可开关项不用考古。

### 两个本机会踩的坑（已写进脚本）

1. **`am start` 在 force-stop 之后拉不起来**（打印 Starting 但进程不存在，Flyme 拦）。
   可靠做法：`adb shell monkey -p com.aiface.app -c android.intent.category.LAUNCHER 1`。
2. **`adb push` 不能用 `/tmp/xxx`**（Windows 版 adb 认不了 MSYS 路径，静默失败后
   `run-as cp` 报 No such file）。要 push 仓库里的相对路径文件。

### 顺手修的脚本 bug（commit da9c4f6）

昨天加的能力清单真实性检查**一直是空转**：12 项探测全返回 `000`，而 `000 != 404`
所以照样判通过。两层原因——
① 本机 `http_proxy` 让 curl 连不上局域网 → 脚本开头 `export no_proxy='*'`；
② **Windows 上 python3 的 stdout 把 `\n` 翻成 `\r\n`**，命令替换只吃掉尾 `\n`，
   于是 `path` 末尾残留 `\r`（`od -c` 实测是 `/render\r\n`），curl 拿到非法 URL。
   → PROBE 管道末尾加 `tr -d '\r'`。修完 12 项都拿到真实码（GET /render→405、
   POST /message→415，都不是 404）。

**教训：凡是 `$(python -c '...')` 生成的行再喂给 shell 变量，都要先 `tr -d '\r'`；
而且断言"不等于某个值"的检查必须能看到真实值，否则 000 会一路绿灯。**

## 产品形态变更（commit b48c04c，魅族 M6 Note 真机验证）

1. **「投送权限」整节删掉，开关上移进「访问模式」第一行，成为总开关**。
   关掉后：mDNS 照常广播（TXT 增 `accepting=0`）、`/info` 照常返回但新增
   `accepting:false` + `acceptingHint`（一句可直接转述给用户的话）、
   `POST /render` → 403 `cast_disabled`。CLI `discover` 带出这两个字段，
   `render` 撞上 `cast_disabled` 时原话转告（别让 agent 自己重试）。
   SKILL.md 新增「发现得到 ≠ 能投」小节。
   → 实现要点：`Prefs.castEnabled`（还是 `allow_render` 这个键），
   `Server.CAST_DISABLED_MSG` 让 /info 的 hint 和 403 的 message 同源，
   `hasPerm("render")` 也复用同一句。
2. **访问模式 = 两行开关**：① 投送 ② 密码验证（默认关 = 公开）。
   打开密码验证才展开单行密码框 + 「确认」按钮（去掉了二次确认密码）；
   关闭时不校验旧密码，直接 `Prefs.clearPassword()`（清 pwd/pwd_hash/pwd_salt）
   + `Auth.revokeAll()` —— 少了 revokeAll 就等于没关，旧 token 照样能写。
3. **历史入口**：原生时钟顶栏齿轮左边加「历史」按钮，删掉首页右滑手势
   （电视 D-pad 左键保留）；HTML 主题浮层本来就是 历史/设置 两枚，没动。
4. **极光主题不再被拖动**：根因是 `.stage` 用 `position:absolute` + 光斑溢出，
   文档出现可滚区。改成 `position:fixed` + `overflow:hidden`（**不能写 inset**，
   电视 Chromium 66 不支持）+ `touch-action:none` + `overscroll-behavior:none`，
   JS 再吞 touch*/dragstart 并在滚动时归位。

### 新技能：CDP 直连 WebView 取值（比截图/Aiface.emit 更硬）

debug 包开了 `WebContentsDebuggingEnabled`，可以绕开页面配合直接量 DOM：

### Compose 焦点的坑：clearFocus 写在 click 回调里不管用（commit 0d8ac96）

现象：关掉「密码验证」开关，焦点会跳到页面最上面的设备名称输入框。
三次尝试才修好，值得记：

1. 在 `onCheckedChange` 里 `clearFocus()` —— 无效。回调执行时密码框还在树上，
   等它被移除，系统做一次焦点搜索，落到最近的编辑框（正好是设备名称）。
2. 挪到 `LaunchedEffect(pwdOn)` 里（重组之后再清）—— 还是被那次搜索覆盖。
3. 延迟 120ms 再 `requestFocus(密码验证开关)`，同时把**设备名称改成「点一下才编辑」**
   （非编辑态压根不是输入框，磁铁消失）—— 才彻底干净，现在关闭后无任何 focused 节点。

推论：Compose 页面里常驻的输入框就是焦点磁铁，凡是"条件性移除某个输入框"的
场景，都得先想清楚焦点往哪儿去。
