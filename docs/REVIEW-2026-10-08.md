# AiCast（爱投屏）代码通读：Bug / 优化点 / 升级路线（2026-10-08，只读评审，未改代码）

范围：`app/src/main`（Kotlin + Compose + Ktor + WebView）、`skill/bin/aicast`（Node CLI）、构建配置与 `docs/DESIGN.md` 对照。
结论：M1 骨架完成度不错（分层/权限/家模式/媒体 Range 拉流都做对了），但**服务端生命周期、事件 seq、媒体配额、权限覆盖**四处存在会真实出错的问题；文档与实现已明显漂移。

## 一、会直接出错的 Bug（优先修）

### 1. Media 配额反噬：上传成功但文件立刻被删
`Media.QUOTA_BYTES = 32MB` 而 `Media.MAX_SINGLE_BYTES = 64MB`，`enforceQuota()` 的淘汰循环只判 `total > QUOTA`，不保护刚写入的那一项：

```kotlin
cur.add(0, meta)                       // 新项在头，最旧在尾
while (total > QUOTA_BYTES && cur.isNotEmpty()) {
    val oldest = cur.removeAt(cur.size - 1)   // 只剩新项时，删的就是新项自己
```

后果：上传 33–64MB 的文件 → 返回 `200 {ok:true,id:"m_xxx"}` → 随后大概率 404（`"gone"`）。
修：`while (total > QUOTA && cur.size > 1)`，并在 `/media` 预检阶段就用 `min(MAX_SINGLE, QUOTA)` 做上限；超配额时回 507 而不是先收下。

### 2. 事件 seq 不持久、也不外露 → agent 重启后永久失联
`CommandBus.seq` 是进程内变量，app 重启归零。agent 端 CLI 把 `since` 存进循环状态（`cmdEvents` 里的 `since = Math.max(...)`），一旦设备重启，`since=N` 永远大于设备侧 seq，事件再也不会返回。
而 `CommandBus.lastSeq()` 写了却没人调用，`/state` 也没带 lastSeq —— 没有任何手段让 agent 发现"seq 被重置了"。
修：seq 落盘（SharedPreferences 单调递增）；`/state` 增加 `lastSeq`；`/events` 在 `since > lastSeq` 时返回 `{reset:true, lastSeq}` 让 agent 归零重来。

### 3. Server 生命周期：引用丢失 + 端口重复绑定崩溃
```kotlin
fun start(): Any = embeddedServer(CIO, ...) { ... }.also { it.start(wait = false) }
```
- 返回 `Any` → 拿不到 engine，**永远无法 stop**；
- `AiCastService.onDestroy()` 里 `serverUp = false`，但旧 server 还在监听；service 若在同一进程内被重建（START_STICKY / 手动 ensure），`if (!serverUp) Server.start()` 会二次 bind 43210 → `BindException` → onCreate 抛出 → 崩溃循环；
- 端口被别的 app 占用时同样无任何兜底。
修：`start(): CIOApplicationEngine` 保存引用；`onDestroy` 真 stop（或干脆不置 false）；start 包 try/catch + 端口回退（43211…）并把实际端口写进 `/info.app.port`。

### 4. 返回键退出后，/render 静默"成功"
`onBackPressed → else -> finish()` → `onDestroy` 把 `App.webView = null`，但前台 Service 和 HTTP server 继续跑。此后 `/render` 仍然走完流程返回 `{ok:true,type:"render"}`，而 `App.webView?.loadDataWithBaseURL(...)` 是空安全跳过 —— **内容永远不上屏，agent 却以为投成功了**。
修：`/render` 先判 `App.activity/webView == null`，要么 `startActivity(FLAG_ACTIVITY_NEW_TASK)` 拉起界面再投，要么返回明确错误码（如 `409 {code:"no_display"}`）。`/state.activityAlive` 已有这个信号，但 render 没用上。

### 5. 事件 kind 未转义 → JSON 注入；页面可伪造系统事件
`eventsSince()` 手写拼接：
```kotlin
"""{"seq":${e.seq},"at":${e.at},"kind":"${e.kind}","data":${e.data}}"""
```
`e.kind` 直接来自 `JsBridge.emit(type, ...)` 的页面可控字符串，未转义 → 页面调用 `AiCast.emit('x","data":{},"kind":"y', …)` 就能污染整条 `/events` 响应，agent 端 JSON 解析直接崩。
同时 `JsBridge` 只在 `type` 不含 `.` 时加 `ui.` 前缀，**页面可以 emit `system.page` / `auth.granted` 这类系统事件类型**，agent 无法区分来源。
修：kind 走 `JSONObject.quote`/serialization 序列化；页面来源强制前缀 `page.`；`system.*`/`auth.*` 仅 app 内部可发。

### 6. 删除类接口零权限校验
`/media` POST 复用了 render 权限，但：
- `DELETE /media?id=` —— 无任何 `Prefs.isOpen` 判定；
- `DELETE /theme?id=` —— 同上（注释写"复用 render 权限"，代码里没写）。

公开模式下，局域网内任何人可以一次请求清空设备上的全部媒体/主题。修：删除统一走 render 权限；更好是拆出独立 `media` 权限项。

### 7. 删除当前主题后界面不刷新
`Themes.remove()` 里 `if (Prefs.theme == id) Prefs.theme = NATIVE`，但没有 `HomeRefresh.invalidate()`；`Server` 的 `delete("/theme")` 只在 `removed` 时调了 invalidate，而 remove 内部才改 Prefs —— 顺序上界面拿到的还是旧主题，屏幕一直停在已删除的主题上直到重启。

### 8. POST_NOTIFICATIONS 从未申请
README 说"首次运行点『允许通知』权限"，但代码里没有任何 `requestPermissions`（全仓库仅 manifest 声明）。Android 13+ 上前台服务通知不会展示，用户无法感知"app 还在跑"，也无从点回界面。

## 二、中等级：逻辑缺陷与一致性

| # | 位置 | 问题 |
|---|---|---|
| 9 | `Server /render {url}` | 无 scheme 白名单，`javascript:`/`file:`/`content:` 都能被 `loadUrl`；也是一台可被任意网页驱动的 SSRF 显示器。应只允许 `http/https`。 |
| 10 | `Params.set("brightness")` | 只写 sp + 改当前 window；Activity 重建/冷启动不恢复，重启后亮度回到系统值但 `/param` 仍报告旧值。应在 `MainActivity.onCreate` 回放。 |
| 11 | `Params.set("rotationLock"/"idleDimSeconds")` | 接受并回 `ok`，实际不生效；`/param` 的错误提示却把它们列为可用项，误导 agent。要么实现要么从提示里删掉。 |
| 12 | 全局 | 无 `Origin`/`Host` 校验，也无 CORS 头：局域网内任意网页可用 `text/plain` 的 simple request 对 `/render` 做 CSRF 投屏；反过来真正需要回调的页面又拿不到 CORS 许可。建议校验 `Host` 为 IP:43210、非简单 Content-Type 强制预检、对 `/media` GET 加 `Access-Control-Allow-Origin: *`。 |
| 13 | `Server` 门禁 | `gateOpen = ... \|\| Prefs.mode != "auth" \|\| !Prefs.hasPassword()`：切到"需密码"但没设密码时**门禁全开**，而 `/info.authRequired` 与 mDNS TXT 对外仍宣称需要鉴权。模式切换也不吊销已有 token。 |
| 14 | `Auth` / `Prefs` | 防爆破计数在内存，进程重启即清零；密码 sha256 无 salt、比较非恒定时间；token 明文存 sp 且数量无上限；`/auth` 支持 `?token=` 把凭据塞进 URL（易进日志）。 |
| 15 | `MainActivity.syncLayers` | ① `/render` 刚 `main.post`、onPageFinished 还没到时，任何 syncLayers（HomeRefresh/返回键/设置关闭）都会走 `showHomeTheme()` 把待显示内容覆盖掉；② 每次开关设置页都重载一次主题首页（页面状态丢失 + `system.page` 事件刷屏）。应只在"当前不是目标主题"时重载。 |
| 16 | `DeviceInfo.capabilities` | 上报 `tts/volume/vibrate/notify/clipboard/launchApp`，`Prefs.openable` 里还有 `screen/system/screenshot/eval`，**这些端点一个都没实现**；设置页后 4 个开关也是空开关。agent 按画像调用必然 404。 |
| 17 | `PUBLIC_PATHS` 含 `/history` | 认证模式下不验 token 也能读到投送历史（标题/时间/来源/大小）。建议移出公开集合。 |
| 18 | `History` | 单条上限 512KB × 10 条 ≈ 5MB，每次 `/render` 都在 Ktor 请求线程上 `file.writeText()` 全量重写；大内容投送会明显卡住响应。另外 `url` 投送不记历史（只有 html 记）。 |
| 19 | `Media` | TTL 只在下次 `commit` 时才清理，长期不上传则过期文件常驻；`index.json` 损坏/丢失后文件变孤儿；`commit` 抛 `IllegalArgumentException("空内容")` 也被 `Server` 统一回成 507（应为 400）。 |
| 20 | WebView | 没有 `WebChromeClient`：`alert/confirm` 静默失效、console 无输出、`target=_blank` 打不开；没有 `onReceivedError` → URL 投送失败时屏幕空白且 agent 毫不知情（应 emit `page.error`）。 |
| 21 | 事件体系 | DESIGN §7/§9 要求的 `capability.changed`（横竖屏/暗色/低电量）与息屏/亮屏 `system.*` **完全没实现**，也没覆写 `onConfigurationChanged`（manifest 声明了 configChanges，Activity 不会重建，所以连"顺带刷新"都没有）。 |
| 22 | `DeviceInfo.isDpad()` | 只认 leanback/gamepad 特征，多数真电视遥控器上报 false → `interactionModel` 落到 `auto`，agent 拿到的画像失真。 |
| 23 | `AiCastService` / `BootReceiver` / `NsdAdvertiser` | 只接 `BOOT_COMPLETED`（缺 `LOCKED_BOOT_COMPLETED`、`MY_PACKAGE_REPLACED`）；NSD 从不 unregister；通知里的 IP 创建后永不更新（IP 变了还显示旧的）。 |
| 24 | `skill/bin/aicast` | `cmdMessage` 绕过 `api()`：`r.json()` 遇非 JSON/403 直接抛、无超时与 401 处理；`--follow` 无节流；`resolveDev` 对缺 `address` 的缓存记录会 `undefined.toLowerCase()` 崩；`discover` 的 cache 回退分支即使空也照打。 |
| 25 | 文档漂移 | README "当前状态（M1）"把 `/auth`、设置页、主题系统列为"计划中"，实际已实现；DESIGN §15 里程碑同样过期；README 提到的 `protocol/` 目录不存在。 |

## 三、性能与工程化优化

1. **`/events` 500ms 轮询** → 平均 250ms 延迟且白烧调度；改用 `SharedFlow`/`Channel` 挂起等待，有事件即刻返回，超时统一由 `withTimeoutOrNull` 控制。
2. **常驻 `PARTIAL_WAKE_LOCK` + 每 10s 全量网卡扫描 + `FLAG_KEEP_SCREEN_ON`** → 手机当面板时耗电明显。改为：网络用 `ConnectivityManager` 回调驱动刷新；WakeLock 改为按需/带超时；屏幕常留给 M8 的作息定时。
3. **落盘挪出请求线程**：History / Media / Themes 三处 `writeText` 都在 Ktor 线程同步执行，改 `Dispatchers.IO` + 去抖；主题 HTML 每次 `assets.open` 全量读，加缓存（现在每次开关设置页都读一遍）。
4. **手写 JSON 改序列化**：`Server`/`CommandBus` 里 `buildJsonObject` 与字符串模板混用，是第 5 条注入 Bug 的根因；统一走 kotlinx.serialization 数据类。
5. **R8 规则过宽**：`-keep class io.ktor.** { *; }` 几乎废掉 release 的体积优化，收窄到实际用到的部分。
6. **APK 里的残留资源**：`app/src/main/resources/_services/_dns_sd.jar` 与 `_dns_sd/_aicast._tcp.zh_CN`（jmDNS 实验残留）会被原样打进 APK，应删除。
7. **仓库没有 git**（根目录无 `.git`），却已在迭代多个里程碑 —— 先 `git init`（`.gitignore` 已就绪）。
8. **零测试**：`Media.enforceQuota`、`Auth`、`eventsSince` 转义、`Params`、CLI 的 `resolveDev` 都是纯逻辑、极易单测；再加一个对真机的协议冒烟脚本（health→info→render→events→media→clean）。

## 四、下一步升级路线（按优先级）

**P0 · 稳定性与协议正确性（先把"能可靠用"补齐）**
- Server 生命周期（引用/停止/端口回退）；render 无 Activity 时拉起或明确报错；
- 事件 seq 持久化 + `/state.lastSeq` + `/events` reset 语义；
- Media 配额与上限对齐、单文件不被自己淘汰；
- 补齐 `capability.changed`（旋转/暗色/电量）与 WebView 加载失败事件，让 agent 能自适应重渲染。

**P1 · 安全闭环（公开投屏是默认模式，这层必须紧）**
- 所有写/删操作统一走权限判定（DELETE 补 render 权限）；
- `Origin`/`Host` 校验 + CORS 白名单，堵住网页 CSRF；token 不再走 query；
- 密码加盐 + 恒定时间比较 + 持久化防爆破；`/render{url}` 加 scheme 白名单；
- 认证模式未设密码时，UI 明确告警（当前"需密码"其实是全开）。

**P2 · 补完 M5–M8 端点**
- `/eval`（已有开关和 `CommandBus.eval` 死代码）、`/screen`（on/off/dim/night）、`/system`（TTS/音量/震动/通知/剪贴板/启动）、`/screenshot`（PixelCopy）；
- `capabilities` 改为"按真实实现 × 权限开关"动态上报，不再写死；设置页后 4 个开关随之真正生效。

**P3 · 体验打磨**
- 设置页补：隐身（关 mDNS，DESIGN §13 已承诺）、存储占用与一键清理、单 token 吊销与列表、作息定时；
- HTML 主题不再被反复重载；电视端 D-pad 焦点导航与 `isDpad()` 修正；
- 亮度/字号等参数在 Activity 重建后回放；通知里的 IP 随网络更新；补 `POST_NOTIFICATIONS` 运行时申请。

**P4 · 工程化**
- git + CI（assembleDebug / lint / 单测）；
- 建 `protocol/` schema（REST + 事件），Kotlin 与 CLI/SKILL 双向对齐，并同步更新 README 状态表与 DESIGN 里程碑；
- `skill/templates/` 按画像（touch / remote / auto）分目录，配最小可复现用例。

### 验证过程中额外发现并修复：HTTP `Expect: 100-continue` 报文格式错误

- 现象：`curl` 上传 body > 1KB 时（curl 默认会加 `Expect: 100-continue`）报 `Header without colon`，`%{http_code}` 显示 100，客户端无法解析响应。
- 抓包定位（原始 socket）：服务端返回的是 `HTTP/1.1 100 Continue\r\n` **后面缺了终止空行**，随后紧跟正式响应，违反 RFC 7231 §6.2 对 1xx 的要求。
- 根因：**Ktor CIO 引擎自身的问题**，非本项目代码 —— `CIOApplicationEngine` 里硬编码了 `"HTTP/1.1 100 Continue\r\n"`。2.3.12 / 2.3.13 / 3.0.0 均存在；**3.3.3 起才改成 `\r\n\r\n`**。
- 处理：Ktor `2.3.12 → 3.3.3`，Kotlin `2.0.21 → 2.2.20`（Ktor 3 依赖的 kotlinx-serialization 元数据需要更高的 Kotlin 版本）。
  适配的 API 变更：`embeddedServer` 返回值类型改为 `EmbeddedServer<…>`、路由 receiver 不再是 `PipelineContext`（`receiveLimited` 改为 `ApplicationCall` 扩展）、`writeFully` 改为显式导入。
- 修复后：`HTTP/1.1 100 Continue\r\n\r\n` 格式正确，curl 上传 3MB 直接 **200**（不再需要 `-H 'Expect:'` 绕行）。

### release 构建此前一直是坏的（R8 阶段失败）

- **问题**：`./gradlew assembleRelease` 一直卡在 `minifyReleaseWithR8`。不是本次引入的（用基
  线 `f46045d` 起 worktree 复验证实同样失败），也就是说这个仓库从来没产出过 release 包。
- **根因**：Ktor 带了几处桌面 JVM 的软依赖，Android 上不存在且运行时不会走到，但 R8 把「缺类」
  当错误：
  `java.lang.management.ManagementFactory`、`RuntimeMXBean`（`IntellijIdeaDebugDetector`）、
  `org.slf4j.impl.StaticLoggerBinder`、`com.sun.nio.file.SensitivityWatchEventModifier`。
- **处理**：在 `app/proguard-rules.pro` 补 4 条 `-dontwarn`（逐条按 R8 自己生成的
  `missing_rules.txt` 添加），并把评审里提过的过宽规则收窄。
- **结果**：
  - release 包从「构建失败」变为可产出，安装到 Mi 10 实测：**22/22 冒烟全通过 + 无崩溃**，
    媒体上传/下载（字节一致）、HTTP Range 206、主题注册、鉴权与 CSRF 均正常。
  - 体积：`-keep class io.ktor.**` → 只保留 serialization/Content 相关，APK **3.57MB → 3.09MB
    （−13%）**。裁剪后的包已在真机跑过完整冒烟，可放心使用。
