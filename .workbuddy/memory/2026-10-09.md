## 1. /info 上报了不存在的 eval 能力（P1-16 翻版，已修，commit 93b4c86）

起因：给双形态演示收尾时顺手复核画像，发现 Mi 10 的 `/info.capabilities` 里有 `eval`。

实测（均为 `Authorization: Bearer` 带 token）：

| 路径 | 结果 |
|---|---|
| `/eval` `/screenshot` `/screen` `/system` `/volume` `/brightness` `/fontScale` | **全部 404** |

其中 `volume/brightness/fontScale` 是 `/param` 的子键，算合理；`/eval` 才是真问题：

- `DeviceInfo.capabilities()` 的 KDoc 白纸黑字写着「真实可用清单 = 已实现的端点 × 权限开关」（这就是当初修 P1-16 的理由），却仍按 `Prefs.evalEnabled` 追加 `"eval"`；
- `Server.kt` 里根本没有 `/eval` 路由；
- `CommandBus.eval()` **全仓零调用方**，是死代码；
- `docs/DESIGN.md` §5/§10 两张表也把 `POST /eval`、`GET /screenshot` 写成了既有端点——文档层同样失真，尚未一并订正。

改动：
- `DeviceInfo.kt` 去掉 eval 上报并留注释
- `CommandBus.kt` 删除 `eval()`
- `scripts/smoke.sh` 新增「能力清单真实性」组：拉 `/info.capabilities` → 按映射表逐项探测，404 或无映射都判失败。**先在改前的包上跑，准确命中 eval 一项红灯（34 通过 / 1 失败）**，证明这检查不是摆设
- `.gitignore` 补 `__pycache__/`

## 2. 构建链路坏了：Studio JBR 升到 Java 25

`./gradlew assembleDebug` 直接炸：`IllegalArgumentException: 25.0.3`，
堆栈落在 `kotlin.com.intellij.util.lang.JavaVersion.parse` → 是
**Gradle 8.14 内嵌的 Kotlin DSL 编译器解析不了 Java 25**（编译 `.gradle.kts` 那一步），不是 AGP 的问题。

本机除了 Studio 的 jbr（已 25）没有别的 JDK。处理：

- 从清华镜像拉 Temurin 17（Adoptium 官方 GitHub 跳转太慢，8 分钟才 2MB）→
  `C:\Users\wapse\.workbuddy\binaries\java\jdk-17`（仓库外，不入库）
- `~/.gradle/gradle.properties` 写 `org.gradle.java.home=...`（用户级，仓库的 gradle.properties 保持干净）
- **坑**：光配 gradle.properties 不够，`gradlew` 这个 wrapper 脚本本身还要靠 `PATH`/`JAVA_HOME` 里的 java 才能启动，所以每次构建得带上
  `JAVA_HOME=... ./gradlew ...`

结果：`assembleDebug` 58s BUILD SUCCESSFUL、`assembleRelease` 2m55s BUILD SUCCESSFUL（R8 没被带坏）。
